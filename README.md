# ngxz-ya｜机械软件 AI 连接与经验复用工具包

让 Agent 边做事，边留下下次用得上的方法。

把这两行交给能读取本机文件、执行命令的 Agent：

```text
https://github.com/ngxz-ya/ngxz-ya
连接我本机的〈软件名称〉
```

Agent 按 AGENTS.md 下载和部署，先查本机经验，再检查指定软件。缺少方法时先找有许可的开源 MCP 连接方案，不合适再研究官方接口或其他合法方法；核对版本并实测，MCP 名称本身不代表能操控前台。没有可靠方法就报告 UNKNOWN 或 UNSUPPORTED，不假装已经连接。

## 能做什么

- 不绑定模型服务商。不同 Agent 使用同一入口、同一份本机经验。
- 自动建立按软件分开的经验槽，保留通用知识、软件方法、方案和踩坑草稿。
- 任务前查经验、读全文，核对版本和条件；执行后通过单独进程回读，与事先确定的验收值比较。
- 留下目标、参数、步骤、适用边界、软件证据和失败现场。经验保存的是方法，实际操作仍需要可用接口和执行代码。
- YA 面板展示真实任务、检索、经验和结果。有可核对来源才统计 Token；未接入显示“未统计”；面板不再展示节省量或无账单来源的费用。
- 更新程序时保留用户经验和成果；支持本机备份、恢复以及停用错误经验。

## Agent 执行入口

需要 Windows PowerShell 5.1 Desktop、系统 .NET Framework/WPF，以及合法安装的目标软件。其他系统尚未支持。先读 AGENTS.md。

在新下载的源码根目录运行（将软件名替换为用户指定名称）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\启动.ps1" -Software "软件名称"
```

默认部署到系统实际桌面的 `ngxz-ya` 工作区，自动管理程序与运行隔离并打开 YA 面板。已有非本工具目录会拒绝覆盖。再次下载后运行同一入口，会找到同一工作区；升级只更新允许清单中的程序，保留经验、连接方法和成果，并保存升级前备份。`-Workspace` 可指定用户自己的长期目录；内部测试必须指定不存在的新测试目录，不能使用维护者或用户的工作区。`-NoPanel` 仅适合无界面测试。

入口返回环境候选、软件槽、已有连接方法位置和下一步。`METHOD_RESEARCH_REQUIRED` 表示仍需研究方法，`METHOD_AVAILABLE_RECHECK_REQUIRED` 表示须复核旧方法。两者都不代表已连接。Agent 继续按[适配器协议](适配器/说明.md)准备本机方法和任务，通过工作区内的 `连接软件.ps1 -Action Run` 执行。

公开包不附带厂商专用连接程序或知识卡；适配器索引出厂为空。没有 Agent 的本机操作权限、合法软件或可用接口，单凭网址不能完成任务。

做干净下载测试时，只使用本次下载包、新测试工作区和目标软件的官方安装接口；不得从本机旧项目、旧桥接或 Agent 缓存里找现成实现。软件安装探测和可追溯的公开方案研究仍允许。日常使用则继续调用用户选定工作区里的长期经验。详细读取边界见 AGENTS.md；这套说明本身不能限制 Agent 的文件权限。

## 经验放在哪里

桌面 `ngxz-ya` 内：

- `工作区/经验库`：通用知识和按软件分槽的方法、方案、坑及草稿。
- `工作区/连接教练/连接经验`：用户本机审查后的连接方法及验证记录。
- `工作区/运行状态`：本机事件与状态，不公开上传。
- `成果`：每个请求独立的模型、执行日志、读回证据。
- `备份`：程序升级前备份。完整备份使用 `工作区备份.ps1`，包含私人数据，不上传 GitHub。

换 Agent 时仍用这个工作区，不能新建空库冒充接手。旧方法的版本、接口、证据或条件不符时必须重新验证。查询命中、读取全文、实际复用成功是三件事。停用方法保留原始记录，新任务拒绝当作可信经验复用。

通用经验用 `exp_search slot=generic` 查询，再按命中提示用 `exp_get slot=generic` 读取全文（补上关键词或编号）；软件槽单独查询，不会自动混入通用经验。合法候选知识仍通过 `skill_search`、`skill_get` 查询和读取，不当作已验证方法。

## 边界

本包提供连接与经验流程，不能保证任意软件、任意任务都可完成。真实验收只对实际安装的软件、接口和任务有效。批处理通过返回 `VERIFIED_BATCH`、`live_link=false`；打开软件窗口也不等于实时连接。模拟返回 `SIMULATED`，不作为可信工程经验入库。

图形软件完成验证后，Agent 必须在前台打开本次成果，同时显示 YA 面板，确认模型已载入、窗口可见且响应，并保持两个窗口供用户查看和继续操作。只完成后台任务须说明“前台交付未完成”；无图形界面或无法显示时如实说明原因。前台展示和常驻连接分别验收，窗口打开后仍须按实际模式报告 live_link。

“连接软件”的验收还要求能在同一个可见会话里继续创建、修改并实际读回。优先使用已打开且允许操作的软件，在新文档内测试；仅后台生成后再打开文件不算连接成功。YA 使用工作区 `YA插件/打开YA插件.bat` 显示，避免专用命令窗口遮挡软件。

连接后继续下指令，默认修改当前打开的模型。暂不支持某个操作时，Agent 应说明缺少什么，不能擅自关闭软件、重启或重建模型。确需重启须先安排保存并征得同意。每个新任务另行验证；面板中上一任务的 100% 不代表新任务完成。

纯本地模型可以接入相同接口，但自主完成整个流程尚未验收。经验增长也不是模型权重训练；减少时间和 Token 的效果需要实测。

超时或状态提交不完整会阻断后续操作，保留日志、请求和模型。不要清除 blocked、换请求编号强行重试或按进程名结束软件。参见 AGENTS.md 的恢复边界。
