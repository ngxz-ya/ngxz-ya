# 经验库

> **第一步先读 [AGENTS.md](../AGENTS.md) 「第 0 步」。** 首连一条命令（包根）：`.\一键连接.ps1 -Software "<软件名>" -StartDir "<本会话起点目录>"`，按它打印的阶段走。

经验按软件分槽。一个槽只放一种机械软件里的做法；验证来源须看正文与实际证据，槽与槽不混。

用户经验槽出厂为空。随包的原创实测工法放在通用技能库/软件参考下，按软件分开，可通过 skill_search 查询。随包附带 427 张跨软件通用候选卡（`v=0`、`status=candidate`，分 40 类存放于 `通用技能库\<类>\`，根索引 `通用技能库\索引.json`），可用 skill_search 查询；它们是候选指导，不是实测结论，不含任何软件的连接方法。用户有权保存的通用方法仍走原经验分存入口：空分类第一次保存需同时指定cat和大写类别码code；新卡默认v=0，不凭保存成功升级工程验证。

通用候选可通过统一命令入口 `skill_search q=关键词` 和 `skill_get id=编号` 查询、读取。返回全文仍是候选指导，不能因为能读就宣称目标软件会执行。

普通任务经验支持 `exp_done slot=当前槽 tag=当前任务标签 record=本次方法记录.json`。Agent按 `连接教练/方法记录示例.json` 填写真实目标、软件及接口版本、参数、操作步骤、验证方法、失败恢复与适用边界；无需用户写脚本。方法与条件在草稿及正式记录中保留。记录不能用脚本正文代替，调用方注入的可信标志会忽略。旧 `verified=1` 仍只是调用方声明，独立软件回读证据才支持相应验证状态。

配置在 `槽位.json`。当前槽是 `active`。每个槽的目录是 `槽\<id>\`：

- `索引.json` — 正式条目；独立验证来源仍须看全文verification_state、context和原始证据。空列表正常
- `招式库\`、`坑库\`、`零件方案库\` — 正式条目，一文件一条
- `_草稿\` — 还没标记验证的草稿，不进索引

另外四份账，跟槽放在一起，卸载不会删：

| 文件 | 记什么 |
| --- | --- |
| `任务标签.json` | 任务标签倒排。条目仍在各槽里，这是第二份索引 |
| `检索闸.json` | 最近一次检索。写草稿前必须先检索 |
| `已挂清单.json` | 三步闸过关的软件。开槽不算 |
| `消耗.json` | 各槽调用次数，和你自己登记的 TOKEN |
| `流程.json` | 当前任务的自检、验收、打回、举手 |

出厂只有一个底槽 `generic`（未指定软件）。要给某一种机械软件单独记账：

```
powershell -NoProfile -ExecutionPolicy Bypass -File ".\YA插件\本包命令.ps1" slot_add id=app1 title=我的机械软件
powershell -NoProfile -ExecutionPolicy Bypass -File ".\YA插件\本包命令.ps1" slot_use id=app1
```

`id` 用小写英文。软件的中文名写在 `title`。支持清单和适配器准确标明软件与版本；通用库不混入软件专属步骤。

## 先检索，再生成

先按槽，再用任务标签收窄：

```
powershell -NoProfile -ExecutionPolicy Bypass -File ".\YA插件\本包命令.ps1" exp_recall q=孔 slot=app1 tag=孔
```

检索要写 `q=` 或 `tag=`，两个都空会拒绝，不会打开写入闸，也不会把整槽列出来。只写 `tag=` 可以按标签看。`slot=all` 会跨槽搜，调用记在总次数里，不摊到每一个槽。`hits: 0` 也算检索过。它只供查看，不能拿来写草稿；没开任务时也一样，要先按目标槽再检索一次。开着任务时，`slot=all` 或标签对不上，都不能把「先检索」勾上，也不能拿去写这条任务的草稿。最近一次检索必须就是这个任务的槽和标签。标签按逗号或空格分成段，整段相等才算。`q=钻孔` 对不上标签「孔」。

`exp_get`、`exp_done`、`task_open` 写成 `slot=all` 会拒绝。`all` 不是槽，只能用来跨槽检索。命令会给出正确写法：调取是 `exp_get id=条目号 slot=具体槽`，写草稿是 `exp_done … slot=具体槽`，开任务是 `task_open slot=具体槽 tag=标签 title=要做什么`。具体槽用 `slot_list` 看。开着任务时，写草稿的提示会带上这个任务的槽。

`slot_add`、`slot_use`、`exp_save`、`usage_set` 也不能把 `all` 当成槽名。要记账请换一个 id，例如 `slot_add id=app1`。TOKEN 登记写成 `usage_set slot=具体槽 token=数字`。入库写成 `exp_save id=草稿号 slot=具体槽`。

`all` 是保留名。即便库里已经误存了这个槽，调取、写草稿、入库、切换当前槽、登记 TOKEN 和三步闸仍然拒绝，不会把它当普通槽读写。当前槽若被设成 `all`，省略 `slot=` 的这几条也拒绝。跨槽检索会跳过它，只提示里面还有多少条。空的可以直接 `slot_remove id=all` 清掉。索引或草稿里还有条目时，不会只说「有条目不删」：请先迁走 `slot_remove id=all to=具体槽`，不要了就 `slot_remove id=all drop=1`。迁完再按具体槽调取。

命中行给出槽、id、一句话和报错特征。紧跟着的 `get:` 是调取全文的命令，槽用条目自己的槽，不是 `all`。`preview:` 只是一句话的前 80 个字。检索不把整段经验贴出来。没有命中时这两行是 `get: none` 和 `preview: none`。

`exp_get` 不写槽，或写了别的槽，都不会把那一槽的全文读出来。这条 id 若在别的槽，会写明在哪一槽（草稿会标明），并给出带 `slot=` 的命令。哪个槽都没有，会写「其他槽里也没有」。

然后才可以写草稿。没检索，或检索的槽和要写的槽不一致，`exp_done` 会失败。开着任务时，`tag=` 里还要有这个任务的标签，写成别的词或只写在 `k=` 里都不行。半角逗号和全角逗号都算分开。一个任务的标签里不要写逗号。没开任务时不额外要求。写完这一次，闸就关上，下一条草稿要重新检索。

```
powershell -NoProfile -ExecutionPolicy Bypass -File ".\YA插件\本包命令.ps1" exp_done c=招式 t=一句话 k=孔 tag=孔 slot=app1
powershell -NoProfile -ExecutionPolicy Bypass -File ".\YA插件\本包命令.ps1" exp_save id=草稿号 verified=1 slot=app1
```

没有 `verified=1` 就一直停在草稿。本包不代任何机械软件做核对。普通槽还有草稿或已入库条目时不能 `slot_remove`，命令会写明条数；`drop=1` 仍只清误建的 `all`。还没入库的一份草稿用 `exp_drop id=草稿号 slot=具体槽` 丢掉，不删槽，也不删已入库条目。`exp_save` 在这个槽找不到草稿时，会指出草稿实际在哪一槽；已经入库的会说明在索引里，不会再写一遍。入库之后，`任务标签.json` 会按 `tag=` 和 `k=` 重建。这两个可以不同，都会留下。全文文件里的 `tags` 只收 `tag=`，不把关键词抄进去。`exp_get` 在全文前面另写一行 `tags:`，和 `k=` 不同时这一行仍是标签。`m=` 报错特征写进本槽索引，可以拿来检索；命中行上能看到 `m=`。`m=` 最长 200 字。入库时会再查一句话、报错特征、关键词和标签的长度，超了就留在草稿，不进索引。

若当时开着任务，检索还要对上任务的槽和标签，自检项 `search` 才勾得上。顺序是先 `task_open`，再 `exp_search`。

## 分槽存放，一处总览

推荐继续分槽，不要收成一个统一经验包再从一处调。

做法、报错和核对都跟着软件走。并成一个库之后，检索会把甲软件的步骤拿去给乙软件生成。标签可以过滤，但标签一旦漏写，两条就混在一起。分槽把这道墙做在目录上，漏写标签也不会串软件。

「想一眼看完」不用靠并库。`overview` 和面板读取全部分槽，列出已挂、经验条数、调用次数和 TOKEN。这一版实现的就是：分槽存放，一处总览。另有一行 `side`：软件侧条数和调用只在连接登记核对通过（`state=ok`，且这个 pid 的主窗口还在、能响应、看得见，槽号对得上本包里的软件槽）时计入那个槽，否则是 0。进程号读不了、槽号对不上、登记还在但窗口没了，都不算。只是大小写不同则计入那个槽。各槽自己的行仍是台账，不会因为没连上就少掉。读不了的超大 TOKEN 显示未统计。

```
powershell -NoProfile -ExecutionPolicy Bypass -File ".\YA插件\本包命令.ps1" overview
```

调用次数在检索和 `exp_get` 时增加。TOKEN 不会自己出现。从你自己的 Agent 平台用量页抄下来再登记；留空就是未统计。未统计的槽不参加合计，合计行会写 `token_known=已登记槽数/全部槽数`。禁止把估算写成账单。

```
powershell -NoProfile -ExecutionPolicy Bypass -File ".\YA插件\本包命令.ps1" usage_set slot=app1 token=1200 note=从自己的用量页抄的
```

禁止写入破解、盗版或注册机相关内容。写草稿时会拒绝。入库时再查一遍，草稿里后来出现这些词也不会进索引。已经入库的条目后来若出现这些词，检索不把那一条列出来，调取也拒绝，不把全文打出来。这时用 `exp_hold id=条目号 slot=具体槽`：索引脏、全文干净，就按全文把索引改回，不打出原来的句子；改回前再查一句话、报错特征、关键词和标签的长度，超了就不改索引，正文也不打出来。全文脏，就从索引清出并改回草稿，正文不打出来。若已经有同号草稿，清出索引并留下那份草稿，不覆盖。全文不在、只剩脏索引时，同号草稿也留着。草稿仍可调取，改干净后再 `exp_save verified=1`。干净的已入库条目不能用这条清掉。`exp_drop` 仍只丢掉还没入库的草稿；碰到这种已入库条目，会指出改用 `exp_hold`。清单、总览、槽列表和面板快照如果碰到这些词，写「没有列出来」。槽 id 若是这些词里的英文词，开槽会拒绝；已经写进去的，这个 id 也写「没有列出来」。条目 id 若是这些英文词，检索仍列出干净的一句话，命中行和 get 行里的这个 id 写「没有列出来」，路径同样不打出。你刚敲的检索词仍按原词回显。正文里的禁止词仍整条不列出。缺槽、缺草稿或条目时，报错和命令提示里的这个 id 也写「没有列出来」。状态行同样处理。草稿和全文仍原样打出。条目 id 本身不算正文里的禁止词。句子干净时仍可调取，全文原样，所以正文里看得到这个 id；调取行和路径仍写「没有列出来」。`exp_hold` 不会因此把这条清出。正文里真有这些词，仍然不调取，也可以清出。条目里的 sw 若只是这条所在的槽 id，同样不算正文里的禁止词。删掉空槽时，这个槽的调用次数和 TOKEN 一并拿掉；同名再开是未统计，调用从 0 开始。

## 通用技能库（候选）

`通用技能库\` 放跨软件的机械工程通法卡，全部候选（`v=0`、`status=candidate`）。结构和经验槽一样是「索引 + 一条一文件」：根上 `索引.json` 一行一条（`id,c,t,k,sw,v,u,st,risk,trigger,f`），每类一个文件夹 `<两位类号>_<类别名>\`，单卡 `<编号>.json`，本类小索引 `索引.json`。它们不进任何槽的 `索引.json`；`generic` 索引出厂仍是空的。这不是软件槽：`slot_list` 里没有它，`exp_search` / `exp_get` / `exp_done` 也不会读它或写进它。

用法：通过本包命令入口skill_search查询关键词，取得真实编号后skill_get读全文，再以exp_recall查本软件槽的验证方法。随包软件参考与本机候选卡分别存放，不写入用户经验槽；使用者合法自有卡可按经验分存入口新增，并运行00_索引/重建索引.ps1。有卡不等于软件会执行，候选v=0保持候选。

### 工程图建模通法（原 GEN-DWG-001，已合并入通用卡 G-MODEL-004）

按工程图建模或改模：图纸逐个尺寸标号 → 按图建模 → 模型上实测并标同号 → 逐号对照列出不一致 → 修正后再测，直到全部一致。全文用 `skill_search q=尺寸编号`（或 `q=GEN-DWG-001`）找到 `G-MODEL-004`，再 `skill_get id=G-MODEL-004` 读取。可修订：实测发现流程有错时直接改这张卡并写明原因。

## 当前参考适配器与故障阻断

通过本机已审查方法的任务由连接软件.ps1统一执行，保留既有检索、调取、草稿和分槽。真实独立回读的记录保存参数、版本、步骤、实测值、模型及原始日志引用；人工verified=1与适配器自报不能替代独立证据。旧手工条目仍可读，但不是自动可执行经验。

操作期间operation.json保持pending；经验正文、索引、标签或任务存储中断后，包将blocked，正常运行时与入口拒绝继续写。必须先核对模型和记录，不自动回滚、重放或清状态。单文件原子写入不是多文件自动恢复事务。

发布包不能直接复制本地经验库。准备隔离包.ps1重建出厂空账本，排除软件槽、模型、事件及源日志；原数据保留。Token来源与软件经验分别记录，缺失时不估算，节省量未经公平对照为“待对照”。
