# 本机适配方法协议 v1

公开索引为空。Agent 先寻找官方文档或合法开源方法并审查源码，随后在 Check 返回的 `连接教练/连接经验/<slot>` 目录建立本机方法。不要依赖别的 Agent 的隐藏文件。以下是协议示例，软件、版本、来源、哈希和步骤必须来自实际调查，不能照填为验证成功。

首次实现按小步验证：脚本语法 → 官方加载入口 → 独立新文档内的最小操作 → 实际保存 → 重开后的几何读取 → 完整桥接。每步保留原始结果，前一步失败先定位，不反复启动整个软件猜测。接口成员不存在时读取本机已安装版本的文档、示例或实际成员，不凭相似名称猜API；不吞掉保存错误，也不把一串未经实测的候选API当作版本兼容支持。

## 方法登记

首次接入先用工作区中的 `准备接入.ps1 -Software "用户的软件名"`。它生成BOM编码的转发驱动、可配置的独立读取包装与方法草稿，建立准备任务并检索已有经验，不覆盖已有文件。读取包装使用现有运行工具处理原生退出码、stderr、超时与测量数组；Agent只需审查并配置真正重开模型的读取程序。方法.草稿.json不能直接作为已审查方法运行。已存在的方法用 `-Action Check` 做语法/编码检查；完整过程见[通用接入指南](../连接教练/通用接入指南.md)。

`方法.json`：

```json
{
  "schema": 1,
  "software": "与 Check 软件名完全一致",
  "software_version": "实际版本",
  "interface": "实际官方接口名称与版本",
  "mode": "batch",
  "status": "reviewed",
  "sources": ["真实官方文档或开源项目链接及版本"],
  "license_review": "核查到的使用和分发条件",
  "safety_review": "只创建独立文档，参数边界、软件实例隔离及恢复方式",
  "driver": "driver.ps1",
  "driver_sha256": "审查后 Get-FileHash 得到的大写 SHA256"
}
```

mode 为 batch、interactive 或 simulation。reviewed 只是审查记录，不是软件验收。附属脚本/配置也须审查并由驱动校验；不可从不确定位置动态下载执行。连接步骤、安装要求、避坑和窗口打开方式用普通文字写入同目录 `连接方法.md`。完成任务后核心保存 `连接验证.json` 和对应任务证据，连接方法目录不会公开打包。

## 驱动契约

用户要求连接图形软件时，先研究 interactive 方案。前文 batch 示例用于后台任务协议，不是首连交付方案；目标进程内双向通道需由实际连接器实现。后台任务通过后仍不能停止并宣称已连接。确实找不到可用方案时，报告具体调查和阻塞，不把“本包没有附送厂商连接器”当作软件无法连接的证明。

前台通道完成挑战与登记后，用 `连接软件.ps1 -Software 软件名 -Action Connect -TaskFile 本次任务.json` 验收。Connect 带任务时强制检查 interactive 本机方法与已登记的真实前台通道。先核对软件和 YA 在用户桌面可见，再执行、独立读回并再次确认通道，全部通过才返回 CONNECTED_INTERACTIVE。batch 方法会在派发前被拒绝，不能拿后台任务结果顶替。缺少 TaskFile 时 Connect 拒绝执行。后续前台任务用 Run，明确要求后台执行才用 Run -AllowBatch。已完成请求的缓存不能用于另一个软件进程的新连接验收。

驱动是 Windows PowerShell 脚本，接受 `-Action Check|Execute|Verify -Context 文件路径`。核心分别用新的进程调用，顺序固定；Context 是只读输入，含 request、nonce、software、software_version、interface、directory、plan、used_experiences。

- Check：定位实际安装及版本，检查接口/权限/参数边界；不可只看安装名称就宣称授权通过。成功回执 status=READY。
- Execute：消费 plan 的实际步骤和参数，只在 directory 建新成果，拒绝覆盖，保留软件原始输出和子进程 PID/启动时间。不得重放不确定请求。
- Verify：用独立软件进程或真正独立读取接口打开保存的成果，读取实际对象/尺寸等。不读 Execute 的预期值冒充测量，不照抄 plan.expected。

表达式参数、实体数量、实际几何测量是不同指标。只读取参数时名称应明确为参数值，不能宣称包围盒尺寸已实测。仅验证本机某一版本时，不把经验适用范围自动扩大到“该版本及以上”。前台登记另须实现[进程内探针契约](../YA插件/说明.md)，本驱动的后台任务成功不替代它。

每阶段将 JSON 写入 directory 下的 Check.json、Execute.json、Verify.json，退出码 0。回执必须有与 Context 一致的 request、nonce、software_version。异常返回非零并写原始日志。软件子进程超时不要擅自重发或杀进程；核心保留 blocked。

Verify 回执额外包含：

```json
{
  "status": "READBACK",
  "measurements": [{"name": "实际指标名", "value": 20}],
  "artifacts": ["本次任务内实际成果及原始软件日志的绝对路径"]
}
```

还需带前述三个身份字段。所有 artifacts 必须属于本次目录。核心检查文件存在并记录哈希，然后独立比较 measured 与任务事前 expected；协议本身不防御恶意驱动伪造。不得将模拟程序登记为真实 batch。

## 复用原生进程与回执工具

本机驱动可 dot-source 包内 `适配器/运行工具.ps1`：

```powershell
. (Join-Path $包根 '适配器\运行工具.ps1')
$run = Invoke-YaNativeProcess -FilePath $实际官方执行器 -Arguments @($本次脚本路径) -Directory $c.directory -Name execute -TimeoutSeconds $c.timeout_seconds
# 软件退出0后，仍须检查本次成果确实保存且有效。
$items = Get-Content -LiteralPath $实际测量文件 -Raw -Encoding UTF8 | ConvertFrom-Json
Write-YaReadback -Context $c -Measurements @($items) -Artifacts @($实际模型,$run.stdout,$run.stderr)
```

这是接口示意，路径必须从实际检查取得。工具不包含软件专属命令或预期测量值。它保留进程句柄，正确读取 Windows PowerShell 5.1 的退出码；stdout/stderr 分开落盘，原生 stderr 中的普通状态文字不自动当作 PowerShell 异常。非零退出或真实超时明确报错，超时不终止软件、不重发，原记录不覆盖。原始输出不等于工程验收，驱动还须核对成果和实际测量。

Write-YaReadback 将测量转成普通 name/value 数组，避免 PowerShell 将数组包装为 value/Count 对象。核心会明确拒绝不符合格式的回执。首次适配先检查 API、实际保存和独立读取，再进入完整验收；不要吞掉异常让出口变成0。

原请求失败后，即使人工改成 completed，也必须通过完整阶段回执、成果哈希及失败记录的一致性检查；新任务不能用状态文字绕过。保留失败，不把排查完成记为任务成功。此一致性保护不能对抗具备同权限、刻意伪造全部资料的程序，宿主仍须约束文件写入权限。

## 任务计划

任务 JSON（数据示意，替换为实际任务）：

```json
{
  "schema": 1,
  "title": "任务简名",
  "objective": "需要完成的实际目标",
  "parameters": {"dimension": 20},
  "steps": [{"action": "驱动明确支持的动作", "description": "可供下次理解的方法和注意事项"}],
  "expected": [{"name": "指标名", "value": 20, "tolerance": 0.001}],
  "recovery": "失败后如何核查现场、避免重复及恢复",
  "applicability": "适用版本、参数和不适用条件",
  "used_experiences": []
}
```

category 可选 招式、坑、零件方案，默认为招式。坑只有在修复方法也经过本次实测时才可信；未解决失败仅留草稿。

## 前台任务的通用驱动

已经完成前台挑战与登记时，优先复用本包 `适配器/前台驱动.ps1`，仍通过上述 `连接软件.ps1 -Action Run` 执行。它处理身份、UTF-8 JSONL、有界读写、任务文件、保存证据和独立读回衔接，不包含软件专属API或SDK，也不会安装、启动、关闭或重启机械软件。

本机 `driver.ps1` 只作转发（放在 Check 返回的软件槽中）：

```powershell
param($Action,$Context)
$pkg=Split-Path (Split-Path (Split-Path $PSScriptRoot -Parent) -Parent) -Parent
& (Join-Path $pkg '适配器\前台驱动.ps1') -Action $Action -Context $Context
exit $LASTEXITCODE
```

方法.json 保留前文全部字段，并添加 frontend：

```json
{"bridge_sha256":"软件进程启动时实际加载并缓存的源码或程序集大写SHA256","reader":"verify.ps1","reader_sha256":"独立读取脚本的大写SHA256","extension":"目标原生格式的小写扩展名"}
```

前台桥在现有进程内探针管道实现 `ngxz-ya/frontend-task/1`，每次回复原样携带 protocol、action、request、nonce；ok 为布尔值。不得仅写一份宣称成功的回执。实际行为由 Agent 使用已审查的目标软件官方API或合法连接方案实现：

- Check：只检查当前进程、版本、活动文档及接口，返回 status=READY、真实 software_version 与 bridge_sha256；哈希必须为加载时缓存值，不能临时读修改后的磁盘文件冒充已加载。
- Execute：消息包含 parameters、steps、output_path；在当前已连接文档执行本次动作，以官方API保存并将本次原生快照放到 output_path，成功才返回 status=EXECUTED、saved_file、software_version、bridge_sha256。不要传回预期尺寸代替几何测量。保存异常必须 ok=false，不吞异常。保留活动文档身份和路径；如软件只能SaveAs导致身份变化，先解决并重新核验，不能伪造旧身份。
- 请求号已由任务入口持久化，超时结果未知时不自动重发。桥接还须按请求号和动作防止重复执行；新鲜QUERY_SESSION检查仍为只读。

Verify 由独立的本机 verify.ps1 实现。通用驱动核对其SHA256，传入 reader-input.json：只有 request、nonce、software_version、directory、model、model_sha256、frontend_pid，不传任务目标值或参数。读取脚本必须用另一个真实软件进程或独立读取接口重开 model，保存原始软件日志，写 directory/Verify.json 并正确返回退出码。Verify.json 除前述 READBACK、measurements、artifacts和身份字段，另需 source=independent_software_reopen、真实 reader_pid（与前台PID不同）、model_sha256。artifacts 必须包含本次原生模型及原始读取证据。核心再与事前 expected 对比，成功后沿用原经验和面板事件。

通用驱动对缺失/空模型、变更哈希、错误版本或旧会话直接失败，原任务保持阻断。独立读取字段仍是经审查适配器提供的证据，不是密码学认证；必须核对真实进程、原始输出与模型。它不使尚未实现桥接或读取API的软件自动变成支持。

前台通用任务入口还按真实软件PID及启动时间持有跨工作区互斥锁，覆盖整个任务。仅针对这个已核验进程，在本机YALink/frontend保存当前请求的原始状态引用；前次请求未完成时，新工作区也不能绕过blocked。共享的是同一软件进程的执行保护，不共享经验、模型或Token；不扫描旧连接目录。原始状态缺失、损坏或未完成时保留现场并人工核查，不自动清除指针。旧版本客户端或绕过入口的外部程序不受此锁约束。

读取脚本调用原生软件进程时，将stdout/stderr分别保留为文件，记录实际PID和启动时间，等待退出后检查ExitCode与本次原始结果。PowerShell的NativeCommandError不等于软件实际失败，原生进程也可能退出0却没有有效结果；两者都须核对。超时保留进程及未知状态，不自动杀进程或重跑。

需要在其他本机适配逻辑中通信时，加载 YA插件/连接上下文.ps1 后调用 `[YaEvidence]::SendMessage(pipe,pid,process_start,message,timeoutMs)`。message 为 Dictionary<string,object>，嵌套参数先用 ConvertTo-Json -Depth 30 和 JavaScriptSerializer.DeserializeObject 转为普通JSON数据。工具核对实际管道进程、完整换行帧和请求身份，不会重试；回复的ok和业务状态仍须检查。不能仅凭助手退出0或文件存在声称工程成功。

不设置 tolerance 时逐字比较字符串；数值比较必须给出有限非负 tolerance。二次任务真正采用旧方法时，先全文读取，添加 `used_experiences: [{"id":"实际编号","reason":"采用原因","applicability_check":"逐项检查结果","steps":[0]}]`，steps 为对应计划步骤的零基编号。不能只为增加计数而填写。核心拒绝停用、未独立验证、版本/接口不匹配或原证据已变化的经验。

从长期工作区运行，实际路径替换示意值：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\连接软件.ps1 -Software "软件名称" -Action Run -TaskFile "本次任务.json" -RequestId "32位小写十六进制请求号"
```

连接验收用 Connect；上例用于已建立通道的后续任务。只有用户明确要求后台执行且方法为 batch 时，才在上例加 `-AllowBatch`。

RequestId 默认自动生成；任务已发出后不要换编号绕过故障闸。成功返回经验编号、请求号、模式与证据目录。相同请求、计划和方法只返回已验证缓存，不再次操作。批处理返回 VERIFIED_BATCH/live_link=false；simulation 只留草稿，不计工程验证/成功复用。

Run自动用task=关联当前任务、用标题检索本软件既有经验，不拿新请求号过滤旧任务记录；排序和原经验存储不变。检索结果只是候选，Agent仍须先用exp_get读全文、核对条件后把实际采用的方法写入used_experiences。已完成前台挑战的通用驱动另行核对当前通道后报告live_link；缓存命中也重新检查连接态，不把历史连接当作仍在线。

失败保留现场并生成待排查坑草稿；原因和修复没有验证前不能写成已解决。任务提交涉及多个文件，中途失败必须人工核对，不自动回滚工程成果。没有软件接口仍要如实停止。

## 验证后的前台交付

对有图形界面的软件，优先复用已打开且允许操作的实例。先加载桥接，确认活动测试文档和窗口，再按 ya_link 挑战、软件通道读回和登记流程核验。登记后用带任务的 Connect，在同一可见会话中创建对象、修改同一对象并实际读回。Connect 完成独立复核和 YA 可见性核验后才报告前台连接成功。将窗口身份、成果路径与核查证据留在本次任务目录，成功的加载和连接方式写入本机连接方法.md。

交付后保持软件、成果和 YA 可见，等待用户继续操作，不自动关闭、隐藏或最小化。后台验证与前台展示分别报告；前台未完成不得报前台 PASS。此步骤不改变 Check/Execute/Verify 契约，也不把 batch 或打开窗口升级成 live_link=true。持续连接须另行验证，不能手工伪造面板连接状态。
