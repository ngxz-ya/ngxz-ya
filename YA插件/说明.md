# YA 插件：本包真实记录面板

> **第一步先读 [AGENTS.md](../AGENTS.md) 「第 0 步」。** 首连一条命令（包根）：`.\一键连接.ps1 -Software "<软件名>" -StartDir "<本会话起点目录>"`，按它打印的阶段走。

双击打开YA插件.bat；同包已开面板时显示原窗口，不结束别的面板或机械软件。

面板按包路径隔离，库固定为本包经验库。它只显示记录和检查进程状态，不代替软件执行器。

Agent 应运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\YA插件\show_ya.ps1`。这个入口明确启动到用户交互桌面，返回本次真实窗口的 PID、启动时间和句柄；非零退出表示未确认用户可见，不能用旧 hud_view.json 或后台宿主的 PID 代替。启动失败保留 hud-show 请求证据，不自动结束旧面板、不重新操作机械软件。旧面板确实占用同一包时由用户正常退出，再调用显示入口。

显示验证核对 WinSta0\Default 输入桌面、实际窗口归属、非最小化/非隐藏状态、屏幕交集及窗口上的可见采样点；进程存在和 WPF IsVisible 本身不够。不能据此保证用户以后切换桌面或手动隐藏后仍可见。首次打开默认置顶，已有明确位置/置顶设置保留。-Preview 不写正式显示证明。

## 连接状态

连接验收时显示入口加 `-WithSoftware`：只处理 link.json 已核验的软件进程，在用户桌面恢复/展示该窗口并再次确认软件和 YA 都能看见，不重启软件、不改模型。Connect 和 ya_link 已使用这个流程。单独查看经验时不加该开关即可，不要求先连接软件。不能把启动辅助进程的 PID 写成 YA 窗口 PID，结果中的 pid 才是实际面板进程。

完成 ya_link 挑战、同包同会话读回和窗口核验后（握手已通），面板显示「已连接 · 软件名」。带 TaskFile 的 Connect 完成轻读回（建一个简单特征、独立读回核对尺寸和面数）与 YA 可见性核验，并为当前登记会话写入验收记录后，显示「已验收 · 软件名」。可见指窗口未最小化、未隐藏、在交互桌面上，被别的窗口盖住也算。软件重启换了新进程时，启动软件.ps1 会对新 PID 自动 prepare=1（同一可执行文件时），面板从「已掉线」回到「已打开 · 待读回」；旧进程的 frontend 登记自动归档。任务完成度一栏只显示两项：「经验 已调用/未调用」「结果 已核对/未核对」，完成度按这两项和已验收三段计。缺回执时显示「待读回」，进程消失、窗口不可见或无响应分别显示原因。

官方Journal批处理退出后显示“未连接”是正确状态；批处理模型及经验验证结果仍可以显示。没有完成常驻实时编辑验收，不得用绿色连接态替代。

任务完成度、经验数量与连接态分别取数。Run 写入的连接验证.json 中 verified=true 表示该任务软件回读通过，mode=batch 表示批处理。打开软件或显示 YA 后，按连接教练/连接经验/说明.md 发起挑战、取得软件读回并登记，再用带任务的 Connect 做前台验收。面板核对的验收记录绑定到登记会话和任务证据，换会话后重新验收。

## 当前数据来源

- 经验库：主面板按原版显示“经验库 N 条 · 新收 M 条”，库存汇总本工作区的正式条目及本机合法候选知识，不在主卡拆分通用/软件。底层软件分槽和隔离仍保留，显示合计不代表经验可跨软件直接执行。“正式”不等于均独立核验，须点开查看状态与证据。
- 检索/调取：来自本包命令入口写入的runtime事件；不把命中当成复用。
- 新增验证/成功复用：来自真实独立软件读回之后的experience_verified事件，按对应任务统计；同请求缓存命中不额外计为一次建模复用。
- 用时：来自持久化实测事件的软件执行与独立回读耗时，悬停可看检索/调取耗时。没有实测事件时显示“未统计”，不以面板打开时间冒充软件耗时。
- 任务：当前任务或最近归档任务。参考实验的“已验收”是自动几何检查验收，记录备注明确仍待用户进行包级人工验收，不表示已生产发布。
- Token：仅读取本包io/actual_usage.json中的runtime_measured记录。没有源则“未统计”；会话累计和首次挂接后的任务增量分开，详情可见来源与时间。界面不再展示节省量或无账单来源的费用估算。

点击经验查看可展开的方法、条件与验证记录；点击Token查看实测用量来源。右键“总计”恢复原版分组布局，展示本次、经验库、本次任务和本工作区累计；库存非零时显示分类与核验记录条形，悬停可查看真实条数。Token构成仅在有完整实测输入/输出来源且没有不明重置拆分时显示，不套用某模型价格。会话累计快照去重，无实测来源仍显示“未统计”。原始事件仍保存在本包HUD的events目录，不默认弹出JSON。重置统计需确认，仅设置显示基线，保留任务、经验、模型、真实事件和平台用量；不将未知Token变成零。

长期工作区的HUD数据在工作区/运行状态；TestCopy仍按本机YAHud/instances/包路径标识隔离；hud_view.json是实际渲染值的核对快照，不是模拟数据源。模拟测试必须使用自己的fixture和HUD目录。

## 显式接入真实用量

Agent 应主动完成“发现来源 → 核对本会话 → 选择现有采集格式 → 接入 YA → 对照显示”。只检查运行环境直接提供的 usage、官方导出或明确给出的本会话日志地址；不了解格式时上网查对应平台官方说明。不得扫描整机、用户目录、Agent缓存或其他会话来找日志和凭据。没有现成格式时，只能从真实 usage 按下述 UsageJsonl 契约作可追溯转换，不能手填或猜数，也不要修改下载包核心程序来伪造支持。仅有人工账单快照时单独说明，不能作为自动实测导入。

首次建立任务后尽早挂接，首次快照用于基线；随后真实任务产生新用量时，对照来源、actual_usage.json 的会话累计与任务增量、YA 显示是否一致。不能为凑数字额外发起模型请求；终态才提供 usage 的客户端需等本次真实任务结束。切换任务须更新 -Task 并重新建立基线。无法取得来源时报告“未统计”及原因（客户端未导出、权限不足或格式尚不支持）；需要额外授权则仅暂停用量部分，不影响软件连接。只设置 log= 或看到数字不等于接入验收通过。

Agent确认本次日志来源后，可执行下列参数化入口；尖括号是需要Agent从当前运行环境取得的值，不是可照抄的文件名：

```text
powershell -NoProfile -ExecutionPolicy Bypass -File ".\YA插件\采集真实用量.ps1" -Log <本会话JSONL> -Session <会话ID> -Task <任务ID> -Follow
```

内置原生日志采集器目前识别 Codex session_meta/turn_context/token_count 格式。每五秒共享只读当前日志，校验会话与input/output/total，不复制对话内容。退出该采集进程即停止。已记录的用量可能滞后，来源时间在详情中保留。

其他运行环境可使用同一采集入口，追加 `-Format UsageJsonl`，不限定 Agent 或模型厂商。Codex 原格式仍为默认值。Antigravity CLI 的官方 json / stream-json 终态用量可追加 `-Format Antigravity` 接入；`-Session` 必须填写原始 conversation_id。采集器只计终态累计 usage，不重复叠加 step_update；thinking 和缓存字段保留但不重复加到总数。没有导出模型时显示 UNKNOWN，来源时间明确标记为导出文件修改时间。首次挂接建立基线，因此单次已结束会话只提供会话累计，不能倒推此前任务用量。此接入已经通过格式回归，真实平台用量仍须逐次对照原始来源；桌面聊天界面没有导出 usage 时仍是“未统计”。识别到 Agent 或填写 log= 不会自动产生 Token 数字。

UsageJsonl 每行是一个完整 JSON 对象，必需字段：`schema=1`、`type=usage_snapshot`、`scope=session_cumulative`、`timestamp`（带时区时间）、`agent`、`provider`、`model`、`session`，以及 `usage.input_tokens`、`usage.output_tokens`、`usage.total_tokens`。输入输出为非负整数，总数必须等于二者之和。同一文件只含一个稳定会话的单调累计值；不要把单次请求用量直接当累计值。首次挂接建立基线，任务只计算挂接后的增量；重复快照不累加。更换任务建立新基线，不追溯猜算此前消耗。

该格式是运行环境接入契约，必须由经过核对的采集适配器从真实运行日志或服务商 usage 返回转换，保留原始用量证据及字段映射；不能由 Agent 手填数字、估计或将用户账单截图伪装成自动实测。格式校验能检查字段与计数一致性，不能证明导入文件的作者或真伪，也不是数字签名认证。只有实际对接并比对原始来源后，才能报告该平台用量采集通过。权限只授予本次会话的用量源，不遍历其他会话；没有可读取来源时仍显示“未统计”。

平台未提供来源、没有相应适配器或日志没有真实usage时，保留“未统计”；旧log=指针本身不会自动变成实测值。不同模型共用会话时，累计不能全部归属最近模型；人工平台快照导入与跨工作区/平台全局总账尚未实现；“总计”仅汇总本工作区已接入的真实会话。缓存输入包含在input_tokens中，不从总量中随意扣除，不按某一家价格猜费用。

统一入口及常驻连接协议见README、AGENTS.md和连接教练说明。面板不是恶意本地代码的安全隔离边界，详细记录可能含本机路径，不应直接发布。
# 前台连接的进程核验

Windows 前台登记还要求目标软件进程内的本地探针通道。仅写入 `channel=software`、复制 PID 或随机数不再能登记成功。旧方法和经验保留，旧连接须重新核验；只有批处理时仍报告 `VERIFIED_BATCH / live_link=false`。

本机适配器在目标 GUI 进程内建立名称为 `ngxz-ya-<32位小写十六进制>` 的双向命名管道，并持续接受连接。软件通道生成的原有 readback.json 另含：

```json
{"probe_pipe":"ngxz-ya-<实际随机编号>","document_id":"当前活动文档稳定标识","document_path":"软件API返回的完整文档路径"}
```

原有 package_id、slot、session、nonce、pid、process_start、written_utc、channel、software_state 仍须齐全；pid、process_start 和文档信息必须从实际进程及软件 API 读取。示例里的占位内容不可直接当成功回执。

管道使用 UTF-8、每行一条 JSON。核心连接后由 Windows 查询服务端进程号，必须等于目标 GUI PID；随后在同一管道上发送两次不同的只读请求：

```json
{"protocol":"ngxz-ya/session-probe/1","action":"QUERY_SESSION","request":"本次随机编号"}
```

每次响应须包含相同 protocol、原样回传 request，以及从软件实际读取的 pid、process_start、document_id、document_path、object_count、can_execute。object_count 为本次活动文档中的实际对象数，须至少为1；can_execute 是布尔值，只有适配器确有可用的持续操作通道时为true。连接和读回有超时，响应限16KiB；连接被只读存活检查关闭时，服务端应正常接受下一连接。软件API须在其允许的线程调用，不能从后台线程不安全地访问GUI模型。

首次登记要求参考模型已有对象。后续命令允许对象数为0，例如用户明确要求删除全部对象；仍须核对原活动文档及真实操作结果，不将空文档误判为会话丢失。

登记核对两次活动文档一致；正式命令执行前后重新查询该通道，错误请求、错误文档或超时保持失败/待核验，不自动重发。面板的存活检查核对端点仍属于目标进程，不执行修改操作。文档切换后需重新核验，不能借上个文档的连接证据。

这解决“另一后台进程复制目标PID也能点亮”的缺口，不是对任意插件的安全认证。仍须审查适配器源码、持续操作能力及真实几何；软件进程内的恶意代码、进程注入或同权限用户改写程序不在普通文件协议的防护范围。当前门禁仅实现此Windows传输；其他合法MCP/API通道须适配进程内探针或另行实现并验收身份核验，不能退回自填JSON冒充成功。

面板的用户桌面宿主通过本机 WMI 脱离调用方作业启动，再校验实际窗口；Agent 命令结束不应带走面板。宿主禁止该启动方式或无可访问的用户桌面时明确失败，不降级成只创建进程就报可见。
