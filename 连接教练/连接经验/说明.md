# 连接经验（跨软件通用：调用 + 存储）

「连××软件 / 打开××并接上 / 启动××」这类一句话任务，**任何机械软件都走同一套**。换软件不改规则，只增加本机该软件的连接卡。

## 一、调用（先查，命中只读卡照做）

1. 认出是连接类任务（触发词：连、连接、连上、接上、接通、打开、启动 + 软件名）。
2. **先查，不许先上网**：
   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File ".\连接教练\连接经验\连接经验.ps1" find task="连接 软件名"
   ```
   它只读，返回：本包实际存在且合法导入的通法卡编号（出厂无卡不返回）及 该软件槽的连接卡（有就给路径、`v`、前提）。
   再补本槽已验证条目：`ya.ps1 exp_recall q=连接 slot=<槽> tag=连接`（只有 `verified=1` 的会出来）。
3. **命中且有 `fast:` 行（卡里有「快通道」）**：直接跑那一条，别手抄步骤：
   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File ".\连接教练\连接经验\快连.ps1" slot=<槽>
   ```
   它一条命令做完「WMI 脱离 Agent 启动 → 软件进程内读回本次随机数 → 等主窗口 → prepare 新挑战 → Probe 软件通道读回 → 经 WMI 在使用者桌面置前 → `ya_link` 登记（自动传 `log=`/`agent=`/`agent_pid=`；Token 另需接入有来源的采集器）→ 再拉回前台复核」，打出各段耗时，`RESULT: OK` 才算连上。`RESULT: ALREADY_REGISTERED` 表示本包已登记的同一可见会话仍有效，直接继续任务，不启动新进程；它不表示新任务已经核验。`RESULT: BUSY` = 已有使用者的软件窗口开着，不重启不杀；`FAIL` 看 `error: [阶段]` 再查卡「失败处理」。参数不同用 `键=值` 覆盖。只核对、不启动也不探测：同一条加上 `check=1`。连上后要实时改模型：`发命令.ps1 slot=<槽> task=<当前任务编号> cmd="..."`（卡里「快通道.命令通道」列了能发的命令）。
3b. **命中但没有快通道**：只读那一张卡，核对「适用前提」与本机是否对得上（版本、安装路径、许可服务），对得上就照「步骤」做；`v=0` 的卡照做也要逐条核「前台判定」「读回」，不跳检查。卡上参数和本机不一样，只改参数，不重新摸索。
4. **0 命中（首连）**才允许摸索。首连五步，照顺序做，别从头乱试：
   1) 认软件进程名、主窗口标题、安装目录（只定位软件本体，不翻别的项目）；看许可服务在不在。
   2) 优先审查公开合法开源 MCP/方法，再找软件**官方**的「启动时自动加载」出口（启动脚本/宏/插件目录/环境变量）+ 能在软件进程内写文件的 API —— 由软件通道写本次读回，不能由 Agent 自写成功文件（优先搜 MCP / 官方 API 文档）。
   3) 用 `快连.ps1` 同款 WMI（`Win32_Process.Create`）启动，工作文件放 `%LOCALAPPDATA%\YALink\work\<槽>\<包标识>\<会话>\` 纯 ASCII 路径——不要用 `Start-Process`/`&`/`start` 从 Agent 命令里直接起（命令结束软件会被带走）。
   4) 窗口可见 → 按下述协议 prepare → 软件合法通道回应 → 置前 → `ya_link` 核证登记（经 WMI 转调传 `log=` `agent=` `agent_pid=`）→ 再置前复核。
   5) **测通当场存**：照第三节写卡 + 写 `<槽>\快通道.ps1` 适配（负责「准备启动命令行/工作目录/读回文件与合法实时 Probe」，返回 `@{CommandLine;CurrentDirectory;Readback;Probe}`；`Probe` 为接收 challenge 路径并调用运行中软件合法通道的脚本块，不能自行写成功 JSON；旧适配不兼容时先复核升级），`add` 登记；下一位换脑 Agent 就能 `快连.ps1 slot=<槽>` 一条命令连上。
   （以下原规则不变）（**不许**扫描或挪用本电脑上本包以外的项目、旧包、旧副本、旧脚本、旧连接经验）：有本包合法通法时先读，无卡则如实记零命中 → 网上只找合法资料（优先搜 MCP，再官方 API / 启动出口 / 宏 / Journal）→ 只找合法连接、不侵权。摸通后**必须**进入下面的存储流程，不许只留在聊天记录里。
5. 只有窗口置前可见、响应且下述证据门槛通过才登记连接；最终操控验收仍需实时改已有模型并读回。

### 本次证据协议（软件无关）

1. `ya_link.ps1 prepare=1 soft=软件名 pid=主窗口进程号 slot=专属槽` 返回 challenge/readback 路径，状态为「已打开 · 待读回」，不建经验槽。
2. 由运行中软件的进程内 API 或可核查的合法通道读取 challenge，将 `package_id/slot/session/nonce/pid/process_start` 原样写入同目录 `readback.json`，另写 `written_utc`（UTC ISO 8601）、`channel:"software"`、非空 `software_state`（真实读回状态）。禁止 Agent 自写 JSON 冒充；适配应保留调用来源、参数和原始结果供核查。
3. 将软件置前，同参数去掉 prepare 再调用 `ya_link`。它核字段、当前 PID 启动时间、挑战/响应时间及文件时间（120 秒内），保存文件 SHA256；120 秒只限首次登记。登记后持续核对包、会话、进程和原始读回摘要；错包、错进程或内容变化时需重新挑战。窗口与登记有效时仍由实际命令读回确认通道可用。
4. 成功才自动 ensure 本软件槽和首连候选草稿；Agent 补前提、参数、合法通道、证据，再 add 候选卡。软件/接口/环境变化须重验，不自动升为 verified。

通用文件脚本只能核对一致性，不能以密码学证明任意软件内执行；JSON 中的 channel 字段本身也不是证明。真实修改已有模型并读回是最终操控验收，模拟结果不得当真软件证据。


## 二、存储（首次连上后必须留下，换脑能照做）

连上（或确定失败原因）后马上登记，**先查重**：

```
powershell -NoProfile -ExecutionPolicy Bypass -File ".\连接教练\连接经验\连接经验.ps1" find slot=<槽>
powershell -NoProfile -ExecutionPolicy Bypass -File ".\连接教练\连接经验\连接经验.ps1" add slot=<槽> file=<按模板写好的卡.json>
```

- `add` 会：查同槽同启动方式的卡（索引里有，或者这个槽目录里已经有卡文件，都算重复；索引里那一行指向的卡文件已经不在，不算重复；重复就拒绝，提示改原卡补前提/证据）；查必填字段；查禁止词；只收候选，并把 `v` 写成整数 0（写成 1、小数或别的值都拒绝，目录不建）；写入 `连接经验\<槽>\连接卡-<序号>.json` 并更新 `索引.json`。`rebuild` 碰到小数 `v` 拒绝整次重建，不把小数收成 0，索引不改。卡里或文件名里有禁止写入的词，同样拒绝整次重建，不把词写进索引，说明里也不打出这个词。
- 同时按AGENTS的任务与经验流程在软件槽写一条短草稿（`exp_recall` → `exp_done c=招式 tag=连接 slot=<槽>`），一句话里写「详卡见 连接教练\连接经验\<槽>\」。短草稿给 `exp_get` 用，详卡给照做用。
- 跨软件能抽出的通法（去掉菜单、接口、路径）按经验分存入口保存为本机通用候选，有同等条目时先查重，不覆盖原始验证记录。
- 使用者在自己的软件上再核对通过一次，才能把卡里 `v` 改 1（手改并在 `核验` 里写日期和证据），短草稿同时 `exp_save verified=1`。Agent 自己连上一次不算核验。

## 二½、专属经验夹自动建与分存（2026-11-05，所有软件同一套）

- **连上就自动建**：`ya_link.ps1` 登记前调 `经验分存.ps1 ensure soft=软件名 [slot=槽]`，确保 `经验库\槽\<槽>\`（招式库/坑库/零件方案库/_草稿/索引.json）和本目录 `<槽>\`（连接卡）都在。连哪款就有哪款的槽。人不手建；建不出来就不登记，不再落到 generic。
- **槽 id**：给了 `slot=` 用它；没给先找槽位表里标题等于软件名的槽；再没有用软件名转小写英文数字，转不出（中文名）用 `app-<8位哈希>`，同名软件回到同一个槽；转出来的 id 已被另一款软件占了就加 4 位哈希尾（如 `cad-6c56`），再撞就从原 id 加长，两款软件绝不混进一个槽。显式 `slot=` 若同时写了软件名、且这个槽标题已是另一款软件，改按软件名定槽。`generic`/`all` 不当软件专属槽。
- **只搜专属 + 通用**：`经验分存.ps1 find q=词`（不写 `slot=` 时用当前已核对的连接；登记还在但窗口不可见、进程不在、未响应、进程号读不了、槽号对不上本包的槽，都不算已连接，只搜通用；只是大小写不同则用那个槽），只读本槽正式条目、本槽草稿、本槽连接卡、generic 正式区和通用技能库；别的软件槽不读、不整库通搜。`where slot=all` 同样拒绝。`slot=` 只能是一个槽号，不能写路径。已入库又含禁止词的正式条目不列出，草稿仍列出。点名 `slot=` 仍看那一槽的台账。`max=` 只收 1 到 50 的整数。
- **做完任务分存**：本软件做法 `save scope=专属 …`（走本包 `ya.ps1 exp_done`，检索闸照旧；没有已核对连接、或窗口在但槽号对不上时，都不新建槽；草稿没写成时，这次新建的空槽会收回）。跨软件通法 `save scope=通用 cat=类号 …`（候选 `v=0`，自动编号，拒绝软件名和路径，关键词、来源和编号也查禁止词，查同题，跑重建索引，不过就撤回）。条目上读不了的调用次数按 0，不让入库中断。`ensure` 说明里不合规的槽号不回显。`find` 列出通用正式条目时，条目号若是禁止词写成「没有列出来」；草稿的一句话里有禁止词也不打出来。
- **测试包**：`ensure` 照常自动建；`save` 默认拒绝，本轮测试明确允许才加 `allow_test=1`。

## 三、连接卡模板（字段缺一个 `add` 就拒绝）

| 字段 | 写什么 |
| --- | --- |
| `id` | `连接卡-<槽>-<三位序号>`，由 `add` 补 |
| `slot` | 槽 id（小写英文） |
| `别名` | 使用者会怎么叫这个软件（触发词用） |
| `t` | 一句话：用什么办法前台启动并读回 |
| `触发条件` | 什么话、软件处于什么状态时用这张卡 |
| `适用前提` | 合法安装、版本、安装路径参数、许可服务、依赖工具；**本机实测版本**写清 |
| `参数` | 会随机器变的值（安装目录、工作目录、超时），步骤里只引用参数名 |
| `启动方式` | 必须**脱离 Agent 子进程生命周期**（Agent 命令结束软件不能跟着退出）；写清用的机制 |
| `步骤` | 有序列表，每步可照做 |
| `前台判定` | 怎么确认主窗口在前台、使用者看得见（进程号 + 窗口标题 + 前台窗口进程号一致） |
| `读回` | 从软件进程内读回的真实状态，含本次随机数，防读到旧文件 |
| `失败处理` | 已遇到的坑 → 现象 → 处理 |
| `证据` | 回执、读回文件、截图、插件登记的路径 |
| `未验证` | 还没实测过的部分，逐条写 |
| `快通道`（强烈建议） | `适配`（本槽目录下的适配脚本名）、`soft`、`进程名`、`窗口标题`（正则）、`错误标题`、`读回含`、`等待秒`；可选 `命令通道`（`命令文件`/`结果文件`/`命令` 列表/`用法`）。有它 `快连.ps1` 就能一条命令连，换脑不用手抄步骤 |
| `v` | 0 = 候选；1 只能由使用者核验后改 |
| `核验` | 谁、哪天、在哪份包里核过，结果 |

**工作文件放哪**：读回库、启动批处理等运行时文件放 ASCII 路径的 `%LOCALAPPDATA%\YALink\work\<槽>\<包标识>\<会话>\`（安装目录旁，没有中文），不放包内，也不放桌面。这样中文路径不会变问号，测试包也不会被改。

### 已核验操作自动保存

本地适配器支持自动保存时，在连接卡的「快通道.命令通道」中设置 `"经验协议": 1`。命令文件使用 JSON，含 `request`（本次随机编号）和 `command`（原命令）。每个成功响应在 `STATUS OK` 与 `DONE` 之间返回 `YA_REQUEST <本次编号>`。适配器只在目标软件操作完成并取得实测后，再返回一行 `YA_EXPERIENCE <JSON>`。JSON 含原样回传的 `request`、简短的 `title`、可复用的 `method`、可选的逗号分隔 `keywords`，以及 `checks` 数组。每项填写 `name`、`expected`、`actual`、`tolerance` 和适用时的 `unit`。期望值来自任务输入或事先确定的验收条件，实测值来自软件读回。

工具包核对请求、会话与每项容差。通过时自动写入当前软件的正式经验槽，输出 `experience: saved`；已存在同标题同方法时返回已有条目。核验不足返回非零退出码，命令回执保留，不冒充工程通过。每条命令必须关联进行中且已检索经验的任务。旧连接卡仍发送原命令格式，但只记录命令返回，不自动验收或入库；各次回执独立保存，避免后续命令覆盖证据。超时或响应不完整保持 pending，禁止自动重发。公开包提供通用协议，具体软件的适配器和经验留在用户本地。

## 四、硬规矩（所有软件）

前台登记必须实现[YA进程核验契约](../../YA插件/说明.md)：探针在目标GUI进程内，实际读取活动文档并响应本次请求。不要通过独立批处理复制目标PID生成回执。命名管道核验通过仍须真实修改与读回，不证明任意软件已支持。

公开资料优先查合法开源 MCP/方法，再查官方 API；采用前核来源、许可证、署名、再分发和 copyleft 义务，无许可证不等于可复制。优先提炼方法，不批量搬依赖或第三方软件连接卡进出厂包。未验证资料带来源与适用前提作候选；核验后的通法归通用库、软件做法归本软件槽，环境变化须复核。
运行时命令统一走本包 `YA插件\本包命令.ps1`；HUD 的 io、命中计数、日志指针和互斥均按本包路径隔离，不杀别的包窗口。卡头悬停或启动日志显示所属包路径，保持白卡布局。

- **不按进程名杀**：要关软件只按本次新起的进程号 `Stop-Process -Id <pid>`；禁止 `Stop-Process -Name …` / `taskkill /IM …`，会误伤使用者自己开着的会话。
- **前台复核**：`ya_link` 登记后 YA 卡会弹出抢前台，要再把软件置前并复核「前台窗口进程号 == 软件进程号」。`IsWindowVisible` 只说明可见，不等于前台。
- **卡命中计数在包外**：`find` / `快连.ps1` 命中记在 `%LOCALAPPDATA%\YAHud\instances\<包标识>\io\card_hits.json`，YA 卡「经验检索」把同一 Agent 的命中算进去；包内文件不动（测试包零改照样成立）。
- **TOKEN 真数**：当前面板只读本包实际用量文件中的runtime_measured记录；日志指针本身不等于有效用量。须通过采集入口校验会话与usage；没有真实来源显示“未统计”，没有公平A/B显示“待对照”。人工usage_set是手动台账，不自动变成面板实测。
- 连接记录（每次 `快连.ps1` 的耗时、进程号、读回）在 本包隔离的 `work\<槽>\<包标识>\records\`，可直接抄进卡「证据」。

## 首连与复连提速（通用，不绑某一软件）

**首连**（无本包专属卡）与**复连**（本包已有候选/核验卡）耗时不同，不要用同一次秒数衡量。

首连建议顺序（减重复，不降验收）：
1. 按本包README完成来源核对并自动部署长期工作区，读取AGENTS规范；不直接运行下载根。
2. 先Check已有方法；缺方法时按AGENTS继续研究官方API或合法开源方案并审查来源、许可与安全性。没有可靠接口才报告UNKNOWN或UNSUPPORTED；高风险操作另行批准，不借缺失卡或其他项目。
3. **一次**识别：软件真实产品名、主版本、官方接口面、授权/签名约束；写入本包候选（v=0），避免同一信息反复摸索。
4. 启动等待按**实际进程/窗口状态**轮询，`快连.ps1 wait=` 可加大；失败原因写入本包候选「坑」，同会话勿无意义重试同一参数。
5. 连接成功仍须：挑战读回 + 前台可见 + 实时改已有模型并读回。打开窗口 ≠ 连接成功。

复连：优先 `连接经验.ps1 find` 本包专属+通用；命中后再 `快连`/`发命令`。出厂不预置任何软件连接卡。

必要的冷启动与授权等待无法用脚本「消除」，只能避免重复探测与过短超时误杀。

明确指定的槽与软件登记名称冲突时，返回 SLOT_NAME_CONFLICT，保留原槽；核对名称和版本后使用已有规范名称，不自动创建另一个槽。
