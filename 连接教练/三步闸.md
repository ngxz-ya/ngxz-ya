# 三步闸

> **第一步先读 [AGENTS.md](../AGENTS.md) 「第 0 步」。** 首连一条命令（包根）：`.\一键连接.ps1 -Software "<软件名>" -StartDir "<本会话起点目录>"`，按它打印的阶段走。

已挂清单只收走完下面三步的软件。开经验槽、写草稿、跑通 `self_check`，都不算。

本页只说明旧教练记录的顺序闸，不是连接成功标准。先按根目录 AGENTS.md 部署，再使用工作区入口。coach_step、已挂清单和 step_finish 都不能替代前台模型载入、同一会话连续操作及软件挑战登记这三项实际证据。干净测试不得读取旧连接；完整边界以 AGENTS.md 为准。

## 1. 搜公开连接资料

用公开文档查「你已经拥有的这套软件，怎样被外部程序合法调用」。把要点写下来；只记合法连接途径，不写侵权相关内容。

```
powershell -NoProfile -ExecutionPolicy Bypass -File ".\安装卸载\运行时\ya.ps1" coach_start id=app1 title=我的机械软件
powershell -NoProfile -ExecutionPolicy Bypass -File ".\安装卸载\运行时\ya.ps1" coach_step id=app1 step=1 note=公开资料里的连接步骤要点
```

`coach_start` 会准备一个经验槽。这时 `link_list` 里它还在待过关，不在已挂。

底槽 `generic` 不是待过关的软件。`coach_start id=generic`、`coach_step` 和 `coach_fail` 都不会把它写进待过关。请另用一个软件 id。若待过关里已经有底槽，再跑一次会把它拿掉。

`id=all` 也一样不能拿来做三步闸。`all` 只表示跨槽检索，不是软件槽。若待过关里已经有 `all`，再跑一次会把它拿掉，不删别的软件的已挂和失败记录。库里即便误存了名为 all 的槽，开闸、记步骤、记失败仍然拒绝。清掉这个槽用 `slot_remove`，有条目要先迁走或明确丢掉，不会把它当普通槽读写。

## 2. 最短步骤试挂

按你自己机器上的合法安装，用最短的一条路径试着连上。成功或失败都要写人话，至少 4 个字，最长 500 字。失败不要硬记成第 3 步：

试挂成功的标准：软件主窗口在前台正常可见（使用者看得见），并且从软件读回了真实状态。后台进程、隐藏窗口、批处理/命令行无界面运行都不算连上，只能记 `coach_fail` 或写明「未前台连接」。

```
powershell -NoProfile -ExecutionPolicy Bypass -File ".\安装卸载\运行时\ya.ps1" coach_step id=app1 step=2 note=已用本机合法安装按最短步骤试过
powershell -NoProfile -ExecutionPolicy Bypass -File ".\安装卸载\运行时\ya.ps1" coach_fail id=app1 step=2 note=试挂没有成功
```

`coach_fail` 只留失败记录，不进已挂。记失败也不能跳步：没有第 1 步就不能把失败记在第 2 步或第 3 步，没有第 2 步就不能记在第 3 步。即便清单里已经写着第 2 步，只要没有第 1 步，记失败仍然拒绝。已经记下的步骤若短于 4 个字、长于 500 字、没有合格的时间，或含禁止写入的词，记失败同样拒绝，待过关还在，不会写成失败。第 1 步的时间晚于第 2 步时，也不能把失败记在第 3 步。第 2 步已经记下时，记第 2 步的失败也要查这个时间顺序。跳步时待过关还在，不会写成失败。`link_list` 会写出槽、步和原因。槽还在，经验不会因为失败被删。删槽时，同名的已挂、待过关和失败记录一并拿掉，命令会写明是哪一种。已经挂上、又没有经验条目的槽也可以删。索引或草稿还在的槽不删，命令会写明还剩几条、草稿号，以及 `exp_drop id=草稿号 slot=具体槽`。这条只丢掉还没入库的一份草稿，不删槽，也不删已入库条目。`drop=1` 仍只给误建的 `all`。

## 3. 小任务过关

先做一个小任务，并且五项自检都过。顺序写在 `自检清单.md`。`step_finish` 必须打出 `complete: yes`，而且这次通过的时间要晚于第 2 步的记录。通过时间必须是当时记下的时刻（年到毫秒）。空的、单个数字或不成时刻的文本不算通过。更早做完的旧任务不能拿来过关。然后才能记第 3 步：

```
powershell -NoProfile -ExecutionPolicy Bypass -File ".\安装卸载\运行时\ya.ps1" coach_step id=app1 step=3 note=小任务已自检通过
```

跳过第 1 步或第 2 步、小任务没有自检通过、记录太短，这一步都是 `RESULT: FAIL`。待过关里如果已经有第 2 步、却没有第 1 步，第 3 步和 `coach_fail` 仍然拒绝，不会写成已挂或失败。第 1 步还要有当时记下的时刻，而且不能晚于第 2 步；时间是空的、不成时刻，也不能往下走。第 1 步或第 2 步的记录若短于 4 个字，后面的步骤拒绝，这句是「记录太短」，和「没有合格的时间」不是同一句。已经记下的记录若超过 500 字，第 3 步和记失败都拒绝，这句是「超过 500 字」；新记一步写超了，仍是「最长 500 字」。两条不是同一句。同一闸里若有两条第 1 步或两条第 2 步，第 3 步和记失败都拒绝，不会写成已挂或失败；把失败记在已经重复的那一步也拒绝。正常命令写不出两条。已经记下的第 1 步、第 2 步里如果后来出现禁止写入的词，第 3 步和记失败也会拒绝。通过之后，`link_list` 和 `overview` 里 `linked=yes`。清单、总览和槽列表如果后来出现这些词，写「没有列出来」，不把词打出来。槽 id 本身若是这些词里的英文词，也写「没有列出来」。

重记前面的步骤时，比它靠后的记录会作废，要按顺序再记。例如第 2 步已经记下，再改第 1 步，第 2 步就没了。这一步若有多条，再记一次会收成一条。第 3 步不能拿这次作废前的第 2 步过关。新的第 2 步记下之后，小任务也要重新做，而且通过时间要晚于这新的一步。

已经打出 `complete: yes` 的任务，再跑 `step_finish` 不会改通过时间，也不能拿这次去过第 3 步。要在新的第 2 步之后重做，请先验收、打回或举手，再 `task_open`。自检通过之后再检索，不会把已经勾上的五项改掉。进行中的任务如果检索对不上，勾选仍会改回不过。

第 2 步如果没有记下合格的时间，第 3 步也会拒绝。请把第 2 步再记一次。合格时间是这条记录自己写下的时刻，改成空的或随便一个数字都不算。

再跑一次 `coach_start` 同一个 id，不会把已挂打回待过关。还在待过关时再跑一次，仍停在进行中，已经记下的步骤还在。失败之后再开一次，同名的旧失败记录会拿掉，不把旧原因打出来；别的软件的失败不动。第 3 步过关时，同名旧失败也拿掉。已经挂上之后，不能再 `coach_step` 或 `coach_fail`。
