# 通用接入指南

> **第一步先读 [AGENTS.md](../AGENTS.md) 「第 0 步」。** 首连一条命令（包根）：`.\一键连接.ps1 -Software "<软件名>" -StartDir "<本会话起点目录>"`，按它打印的阶段走。

这些是可按实际情况选用的接入线索。Agent 自行决定从现有窗口、包内经验或公开资料入手，最终按 [AGENTS.md](../AGENTS.md) 的三项标准验收。

**连接方法一律先上网找合法开源方案**：GitHub 搜「<软件名> MCP / GUI bridge / 官方 API 名 + example」、[MCP Registry](https://registry.modelcontextprotocol.io/)、官方 API 文档；本包只提供通用脚本链（定位、启动、接口探测、编译、弹窗守护、握手、改模读回、存经验），不内置任何软件的连接实现。 写任何接口调用前先跑 `适配器\接口探测.ps1` 生成能力文件，只用本机版本真实存在的成员；启动和改模期间用 `适配器\弹窗守护.ps1` 静默处理错误弹窗。



## 越界即本轮失败

按 [AGENTS.md](../AGENTS.md) 第 0 步：在当前目录下载解压 → `定位软件.ps1` 定位目标软件 → 每个大步骤前跑 `越界路径审计.ps1`，退出码 2 即本轮失败并停止。不得列举/读取用户主目录、桌面、文档、下载、盘符根、`.gitconfig` 或其他项目历史副本；不得借用本机旧桥接目录中的 DLL。桥接必须在本包或本轮 `artifacts` 生成。

## 本机范围、编码与首连提速

- **本机只能定位用户点名软件的本体安装目录。** 禁止搜索、读取、加载或借用本机其他项目、脚本、DLL、启动目录，以及软件自定义目录中非本包本次生成的文件。连接用桥接必须位于本包目录内或由本包在本轮受管工作区/`artifacts` 任务目录生成；`Assert-YaLocalBridge` / SoftOn 证据闸对包外桥直接拒绝，不计连上。
- **路径编码：** 管道与任务 JSON 一律 UTF-8；成果目录用 ASCII 名 `artifacts`（兼容旧 `成果`）。不要把含中文的成果路径经默认系统代码页再写入原生桥。
- **首连提速（通用）：** 先查本包通用经验与受管工作区已验证方法；优先试用该软件的合法开源或官方接口；说明与探测保持精简，确认窗口与只读通道后再写桥。不预置某一商业软件的连接卡。
- **多版本共存：** 桥接必须匹配**当前目标进程**的实际产品版本，且来自本包本轮产物；禁止从其他版本安装旁路或历史自定义目录加载。
- **启动 GUI：** 用本包 `YaWindow.LaunchInteractive`（已脱离 Agent Job），避免把目标软件挂到会随父进程结束而杀子进程的作业对象。
## 首连参考

1. 运行下载包的启动入口，进入它返回的工作区。查找经验只读本轮下载包和该工作区。包外本机探测仅限目标软件本体安装目录的安装、版本、进程、窗口和官方/开源接口；禁止借用本机其他项目或非本包生成的 DLL/脚本。先看 `installation_candidates`。名称找不到时看 `version_only_candidates`，用候选目录下实际可执行文件的产品名和版本核对。仅版本相同不能据此启动软件。优先复用允许操作的可见窗口。如果有多个实例且无法确定用户所指的窗口，再确认实例。需要新启动时，先核对目标软件能进入可见界面。启动失败就保留原始日志并说明原因，避免先编译整套桥或反复重启。
2. 查本软件槽及 generic 的已有经验。没有适用方法时，可以用实际产品名和版本在 [GitHub 仓库搜索](https://github.com/search?type=repositories) 查 `软件名 MCP`、`软件名 GUI bridge` 或 `软件名 active document`，也可在 [MCP Registry](https://registry.modelcontextprotocol.io/) 按产品名查。优先看能控制已打开窗口和活动文档的方案，再用上游或官方文档核对版本、许可、依赖和加载入口。目录收录只作线索，执行前回原项目核对源码与权限。跳过破解、绕过许可或来源不明的安装包。
   - 外部自动化或会话 API：优先检查能否取得运行中实例和活动文档，并确认它就是目标窗口。
   - 软件内插件、脚本或宏：先检查该版本能否在当前窗口安全加载，并持续接收命令。若必须由人加载，说明所需的一步。
   - 批处理、求解作业或文件交换：单独验证成果。只有软件结果可绑定到正在控制的同一可见工程时，才继续验证前台。
3. 先验证前台只读通道。本包当前只验收目标进程内的命名管道。用经审查的桥提供探针。若外部接口无法提供当前契约要求的证据，保留只读结果并说明缺少核验方式。如登记要求已有对象，用独立测试文档准备一个最小参考对象。按 YA 探针契约读回进程身份和活动文档，然后完成 YA 登记。此时显示「通道就绪 · 待验收」。若通道未建立，记录阻塞在版本、加载还是读回，避免重复跑后台建模。
4. 用下方准备工具生成规范文件，补齐已审查的前台驱动与独立读取程序。运行带任务的 Connect，在已登记的同一可见会话里创建或加载测试对象，修改同一对象，记录对象标识及修改前后的实际值，再保存并独立复核。不同任务用实际可读的证据，例如对象尺寸、工况与求解结果、机构参数与曲线、虚拟机床与仿真报告。数控仿真测试只在隔离的虚拟环境运行。验收后保留窗口，下一条指令先复核同一会话和文档。
5. 将实际通过的版本、加载步骤、失败排查和证据保存到本机。下一次先查这条方法，核对当前会话再使用。准备草稿和仅通过后台验证的记录不得登记为前台连接成功。

所有机械软件的首连采用同一验收标准。只有可见的同一软件会话能持续接受操作并读回，且 YA 登记与任务验收均通过，才报告连接成功。只能后台执行时记录 VERIFIED_BATCH、live_link=false，并报告连接未完成。

遇到「YA 没出现」或「YA 未连接」时，先从工作区运行下面的诊断。分别读取 `hud_visible` 和 `frontend.stage`，按 `frontend.next` 继续。诊断不会执行建模。回复用户时说明当前阶段、实际证据及下一步；仅在确实需要选实例、授权或手动加载时提出具体请求。

若启动检查返回 `FRONTEND_ADAPTER_MISSING`，按第 2 步找兼容的前台方案，优先跑最小只读探针。找不到可用前台实现时，直接报告缺口和证据。环境检查用 Check。首连受阻时说明原因，只有用户明确要求后台执行才使用 Run -AllowBatch。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\连接软件.ps1 -Software "用户的软件名" -Action Diagnose
```

只需打开 YA 面板时，运行 `YA插件/show_ya.ps1`。登记软件通道时，把下方变量替换为已确认的软件名、专属槽和实际 GUI PID。先发起挑战，由进程内适配器写入本次返回的回执路径，再运行登记命令。

```powershell
$target = @("soft=$softwareName", "slot=$softwareSlot", "pid=$softwarePid")
powershell -NoProfile -ExecutionPolicy Bypass -File .\YA插件\ya_link.ps1 @target prepare=1
# 退出码 2 表示等待本次软件回执。收到真实回执后再登记。
powershell -NoProfile -ExecutionPolicy Bypass -File .\YA插件\ya_link.ps1 @target
```

登记时目标软件窗口须置前。登记后用带任务的 Connect 做最终验收。已有有效通道但面板不可见时，可用 `show_ya.ps1 -WithSoftware` 重新显示。

本机探针、编译输出和中转文件也放本轮新目录，不在共享缓存里复用同名文件。程序更新、正常任务使用长期工作区；干净首连测试使用全新工作区，二者不要混淆。

## 直接复用包内辅助

在启动入口返回的工作区运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\适配器\准备接入.ps1 -Software "用户的软件名"
powershell -NoProfile -ExecutionPolicy Bypass -File .\适配器\准备接入.ps1 -Software "用户的软件名" -Action Check
```

New生成UTF-8 BOM驱动、独立读取包装、读取配置及方法草稿，拒绝覆盖已有文件；同时建立连接准备任务，检索本软件槽与generic，让准备阶段也留下实际记录。Check检查本软件槽的脚本语法和编码。生成成功仅代表准备文件有效，绝不代表已经连接。

Agent仍须实现并审查实际读取程序，在reader.settings.json中填写真实可执行文件和参数；参数列表中的{model}、{output}由工具替换为本次模型及新测量文件。读取程序须实际重开模型并输出name/value测量数组，不能使用预期值生成输出。

软件桥继续按适配器/说明.md与YA插件/说明.md实现。原生进程用运行工具.ps1保留退出码和日志；通信复用YaEvidence.SendMessage，不自写无界ReadLine。快连的受控工作进程对适配准备、探针及全流程设期限；超时保留blocked及软件现场，不重发。

正式验收使用连接软件.ps1 -Action Connect -TaskFile，而不是只看快连标记、进程或面板颜色。任务执行前检索，实际执行后独立读取，正确才保存可信经验；失败记录为未解决草稿。

## 获取文件与授权

Windows PowerShell中的curl可能是别名；需要使用原生工具时明确写curl.exe。下载应设连接和总时限，命令等待输入时不要无限等待。下载包中的脚本按说明使用powershell -NoProfile -File执行，避免层层嵌套-Command。

本指南不转载第三方代码、教程或软件资源。公开来源并不自动意味着允许复制分发；使用第三方实现时遵守其实际许可证，保留必需署名与条款。权利或版本不明确就记UNKNOWN，不放入本包，不以删去产品名字代替许可检查。可参考[GitHub关于仓库许可的说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)。

没有真实Token来源就未统计。方法导航能减少重复寻找的机会，但未做有效对照，不宣称已经节省Token或时间。
