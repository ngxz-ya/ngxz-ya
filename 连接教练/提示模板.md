# 提示模板

把下面这段交给 Agent。只找合法连接途径、不侵权；不要点名厂家，不要把示意零件说成已经接通。

```
你在用 YA 工具包。先读本包 AGENTS.md，只走本包脚本。

我自己连接我已经合法安装的机械软件。你不要探测我机器上装了什么；只找合法连接途径、不侵权；不要点名厂家。

连接一种软件必须走三步闸，不能跳。底槽 generic 不是待过关的软件，不要对它 coach_start。
1. 搜公开连接资料，coach_step step=1 写下要点。
2. 用我本机的合法安装做最短试挂，coach_step step=2 写下结果。失败就 coach_fail，不许写成已挂。
3. 在第 2 步之后做一个小任务。先 task_open（slot 写具体槽，不要写 all），再 exp_recall。有命中就按结果里的 get 行 exp_get 沿用；没有命中才生成。然后五项 step_check 都 pass=1，step_finish 必须打出 complete: yes。更早的旧任务不算。之后才能 coach_step step=3。记录短于 4 个字、或已经记下的记录超过 500 字，都不能往下走，记失败也一样复查。同一闸里若有两条第 2 步，第 3 步会拒绝，把第 2 步再记一次就收成一条。slot=all 只能跨槽检索，不能拿来调取、写草稿或开任务。库里如果已经有名为 all 的槽，不要读它。空的用 slot_remove id=all 清掉；有条目用 slot_remove id=all to=具体槽，不要了用 drop=1。已经入库的条目后来若出现禁止写入的词，检索不列出，调取也不打全文。条目 id 若只是这些英文词，命中行仍列出干净句子，这个 id 写「没有列出来」，检索词按原词回显。缺槽或缺这条时，报错里这个 id 也写「没有列出来」。草稿和全文仍原样打出。条目 id 本身不算正文里的禁止词。句子干净时仍可调取，全文原样；不会因为这个 id 把干净条目清出。sw 若只是所在槽的 id，同样不算。删掉空槽会把这个槽的调用次数和 TOKEN 一并拿掉，同名再开是未登记。正文里真有这些词，仍然不调取。用 exp_hold id=条目号 slot=具体槽 清出索引或按全文改回，不要把词打出来。草稿仍可调取，改干净后再入库。清单和总览碰到这些词写「没有列出来」。第 2 步已经记下、时间顺序不对时，记失败也会拒绝。失败后再开闸，或第 3 步过关，同名旧失败会拿掉，不打出旧原因。exp_hold 在全文超出入库长度时不会改索引；已有同号草稿时不覆盖那份草稿。

每一步没有 step_finish 的 complete: yes，就禁止向我报完成。已经 complete: yes 的任务不要再 step_finish，通过时间不会更新。要在新的第 2 步之后重做，先让我验收、打回或举手，再 task_open。
自检通过后，把验收、打回、举手交给我，不要替我选：
- 验收：step_accept。可以不写备注。写了 note= 就不能含禁止写入的词，最长 300 字。
- 打回：step_reject note=原因。打回之后不能再报完成。
- 举手：step_hand note=卡在哪。举手不是完成。

要看挂了哪些软件、每个槽有多少经验、调用了多少次、TOKEN 是多少，跑 overview。
TOKEN 没登记就写未登记。不要编造用量。我如果给了平台上的数字，用 usage_set 记下。

人话任务：我只说要干什么。你按 连接教练\任务验证方案卡.md 定档，先用skill_search查询少量本地合法方法（出厂0卡；只有用户已有合法词表时才使用任务索引），用 exp_recall q=编号 slot=本槽 tag=任务标签 查本软件已验证做法；没有就说本软件还没验证过，不要装会。
汇报分四态：理解了 / 发了命令 / 软件里实际完成（读回证据）/ 核对通过。只有第四态才算完成。覆盖文件、生产程序、驱动设备先问我。缺关键条件就 step_hand 举手列缺项，不要猜。
省没省、快没快须有同任务同验收条件的有/无经验对照及真实用量证据；没有就说未实测，节省待对照。
```
