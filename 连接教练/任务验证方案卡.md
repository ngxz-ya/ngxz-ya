# 任务验证方案卡

人说一句话，Agent 开工前先填这张卡。**不加命令**：卡写在给人的汇报里，按卡走现有的 `task_open` → `exp_recall` → `step_check` ×5 → `step_finish`。

L1 快通道只填前 4 行；L2、L3 全填。拿不准按高一档。

```
任务（人话原句）：
验收：交付物 / 精度 / 不能动的东西
档位：L1 / L2 / L3
技能编号：skill_search实际命中的编号；出厂无卡时记无
本槽已验证：编号 → 命中条目号；hits: 0 = 本软件还没验证过这一步
核对项（给 inspect 用）：1. …  2. …  3. …（每项写用什么证据：读数、对照表、文件回读）
高风险动作：无 / 有 → 先问人，写回退点
缺项：无 / 有 → 分级，关键缺项举手
四态：①理解了 ②发了命令 ③软件里实际完成 ④核对通过
```

## 四态，不能混

| 态 | 什么算到了 | 证据 |
| --- | --- | --- |
| ① 理解了任务 | 方案卡填完、`task_open` 已开 | 卡片内容 |
| ② 发出了命令 | 已在软件里执行操作或脚本 | 操作或命令原文 |
| ③ 软件实际完成 | 读回软件状态，变化确实发生 | 读数、特征、文件 |
| ④ 结果通过验证 | 核对项逐项过 | 核对表 |

- 命令返回成功但读回没变 → 停在②，不是③。
- 只有到④，才能 `step_check item=inspect pass=1`，`step_finish` 打出 `complete: yes` 才能报完成。
- 汇报时写清停在哪一态。失败、要回滚、要人接手 → `step_hand note=卡在哪`。

## 卡和五项自检怎么对

| step_check | 对卡里哪一行 |
| --- | --- |
| `search` | 「本槽已验证」：按编号和任务标签真的检索过 |
| `compare` | 「验收」逐条对过 |
| `draft` | 没有把草稿或候选卡说成已验证 |
| `claim` | 没过三步闸的软件没说成已接通 |
| `inspect` | 「核对项」全过，且到第④态 |

## 连续对话（「长度再加 10」「撤销」「导出 STEP」）

- 还在同一个任务里：按 G-DATA-004 锁定这次只改哪里，改完回到②→③→④。
- 上一个任务已 `complete: yes`：新的修改开新任务（`task_open`），卡可以只写变化的那几行。
- 撤销前确认有可恢复状态；撤销后同样要读回状态（③）。

## 快

- L1：最多读 2～4 张卡；本槽已有 `verified=1` 做法的编号，直接照做，不再读通法卡。
- 不为凑格式加检查。核对项只写这次任务真正要验的。
